# Instruções para agentes

Este é um projeto educacional. O desenvolvedor deve ter a oportunidade de continuar implementando manualmente conceitos e regras novas.

- Por padrão, pedidos de análise, diagnóstico, explicação ou revisão não autorizam alterações.
- Não implemente código sem autorização explícita.
- Explique causas, consequências e alternativas.
- Permita que o desenvolvedor proponha e implemente primeiro conceitos novos.
- Pode inspecionar arquivos, pesquisar referências e executar testes não destrutivos quando forem relevantes.
- Antes de replicar uma mudança, compare os recursos e identifique exceções.
- Ao receber autorização para editar, altere somente o escopo solicitado.
- Preserve alterações preexistentes e não modifique arquivos não relacionados.
- Não altere migrações Flyway já aplicadas sem autorização explícita.
- Não use comandos Git destrutivos.
- Depois de editar, execute os testes relevantes e apresente o resumo do diff.
- Ao revisar testes, verifique se os mocks representam comportamentos possíveis das dependências reais.
- Priorize explicações que ajudem o desenvolvedor a aprender, em vez de apenas entregar código pronto.
